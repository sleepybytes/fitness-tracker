# Installing Fitness Tracker on your iPhone

There are two ways to run the app:

| | How | Needs the Mac running? |
|---|---|---|
| **Dev testing** | `npx expo start`, open in Expo Go | Yes |
| **Standalone app** | Real app icon on your home screen, JS bundled inside | No |

iPhones only install apps signed with an Apple certificate, so the standalone app is built with
one of the two options below. Your logged data lives inside whichever app you use. Data in
Expo Go does **not** carry over to the standalone app.

---

## Option A: Free (Xcode + free Apple ID)

App expires after **7 days**; re-run step 5 to refresh it (your data is kept).

1. **Install Xcode** from the Mac App Store. Open it once and install the iOS platform
   (only the newest one is needed). Then point the command-line tools at it:
   ```bash
   sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
   brew install cocoapods
   ```
2. In Xcode: **Settings → Accounts → +** and sign in with your Apple ID. This creates a free
   "Personal Team". Put its Team ID and your own app ID in a git-ignored `.env.local`:
   ```bash
   cp .env.example .env.local   # then set APPLE_TEAM_ID and APP_BUNDLE_ID (e.g. com.yourname.fitnesstracker)
   ```
   `app.config.js` reads them at build time, so they never go into git.
3. Plug your iPhone into the Mac with a cable, unlock it, and tap **Trust**.
4. On the iPhone: **Settings → Privacy & Security → Developer Mode → On**. The phone restarts.
5. In this folder run:
   ```bash
   npm run ios:device
   ```
   [`scripts/install-iphone.sh`](scripts/install-iphone.sh) builds a **Release** version with the
   JavaScript bundled in, signs it, and installs it on the connected iPhone (~5 min after the first
   build). It calls `xcodebuild -allowProvisioningUpdates` directly, because
   `expo run:ios --device` can't create the signing profile for a free team.
6. First launch only: on the iPhone go to **Settings → General → VPN & Device Management**,
   tap your Apple ID, then **Trust**.

Unplug and use it. No Mac or Expo Go needed until the 7 days are up.

> Tip: [SideStore](https://sidestore.io) can refresh the 7-day signature from the phone itself.
> Install the app once using the `.ipa` from Xcode (Product → Archive).

## Option B: Paid Apple Developer account ($99/yr), no Xcode needed

Builds in Expo's cloud. The app lasts a year. Install from a link, or through TestFlight.

```bash
npx eas-cli@latest login            # free Expo account
npx eas-cli@latest device:create    # register your iPhone (opens a link on the phone)
npm run build:ios                   # cloud build; prints an install link + QR code
```

Open the link on the iPhone to install. For TestFlight instead, use `npm run build:ios:testflight`.

---

### Notes
- **Xcode 27 / iOS 27 SDK** requires the UIKit scene life cycle. Expo SDK 57's template doesn't
  adopt it, so the app would quit right after its splash screen. `plugins/withSceneLifecycle.js`
  back-ports SDK 58's `SceneDelegate`. Remove it after upgrading to SDK 58.
- The app only uses **local** reminders, so it needs no push-notification permission.
  `plugins/withoutPushEntitlement.js` removes it. That is what lets a free Apple ID sign the app.
- The `ios/` folder is generated by the build and git-ignored. Don't edit it by hand.
- After upgrading to Expo SDK 58+, remove `withSceneLifecycle`, run `npx expo prebuild --clean`, and rebuild.
